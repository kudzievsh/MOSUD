# Практическая работа № 2

**Тема:** Множества и мультимножества в SQL  
**Вариант:** 3  
**Штат X:** RS  
**Штат Y:** SC

## Постановка

Множество **A** состоит из `product_id` товаров, которые покупали клиенты штата **RS**, а множество **B** — из `product_id` товаров, которые покупали клиенты штата **SC**. Учитываются только заказы со статусом `delivered`.

В `lab02.sql` выполнены:

- построение A и B и сравнение `count(*)` с `count(DISTINCT product_id)`;
- объединение через `UNION` и `UNION ALL`;
- пересечение через `INTERSECT`;
- разности `A - B` и `B - A` через `EXCEPT`;
- проверка коммутативности объединения и пересечения;
- демонстрация некоммутативности разности;
- реализация пересечения без `INTERSECT` с помощью `EXISTS`;
- проверка эквивалентности `INTERSECT` и `EXISTS`;
- демонстрация появления дубликатов без `DISTINCT` при использовании `UNION ALL`.

## Результаты

### Исходные выборки

| Отношение | Строк с повторами | Различных `product_id` |
|---|---:|---:|
| A (RS) | 6134 | 3939 |
| B (SC) | 4097 | 2740 |

Следовательно, обе исходные SQL-выборки содержат повторяющиеся `product_id`, поэтому без `DISTINCT` они имеют мультимножественную семантику.

### Мощности множеств

| Множество / операция | Мощность |
|---|---:|
| A | 3939 |
| B | 2740 |
| A ∪ B | 5885 |
| A ∩ B | 794 |
| A − B | 3145 |
| B − A | 1946 |

Результаты согласуются с основными равенствами для конечных множеств:

- `|A ∪ B| = |A| + |B| − |A ∩ B| = 3939 + 2740 − 794 = 5885`;
- `|A − B| = |A| − |A ∩ B| = 3939 − 794 = 3145`;
- `|B − A| = |B| − |A ∩ B| = 2740 − 794 = 1946`.

### UNION и UNION ALL

`UNION` вернул **5885** различных товаров.  
`UNION ALL` вернул **10231** строк, то есть все строки исходных выборок A и B: `6134 + 4097 = 10231`.

В результате `UNION ALL` имеется **4346** избыточных повторных строк относительно множества различных `product_id`.

### Проверки свойств операций

| Проверка | `mismatch_count` | Результат |
|---|---:|---|
| `A ∪ B = B ∪ A` | 0 | истинно |
| `A ∩ B = B ∩ A` | 0 | истинно |
| `A − B = B − A` | 5091 | ложно |
| `INTERSECT = EXISTS` | 0 | истинно |

Таким образом, на данных подтверждены коммутативность объединения и пересечения и некоммутативность разности. Пересечение, реализованное через `EXISTS`, полностью совпало с результатом `INTERSECT`; его мощность также равна **794**.

## Множества и мультимножества

Обычные `UNION`, `INTERSECT` и `EXCEPT` в PostgreSQL устраняют повторяющиеся строки и в данной работе соответствуют операциям над множествами. `SELECT` без `DISTINCT` и `UNION ALL` сохраняют повторения, поэтому их результат может быть мультимножеством. В эксперименте `UNION ALL` вернул 10231 строк вместо 5885 различных `product_id`, что наглядно показывает влияние дубликатов.

Порядок кортежей не является свойством отношения. Если порядок строк важен для вывода результата, он должен задаваться явно с помощью `ORDER BY`.

## Вывод

В ходе работы были построены множества товаров для штатов RS и SC и выполнены основные теоретико-множественные операции SQL. На реальных данных подтверждено, что объединение и пересечение коммутативны, а разность — нет. Также показано различие между множественной и мультимножественной семантикой SQL: `UNION` удаляет дубликаты, тогда как `UNION ALL` сохраняет их. Реализация пересечения через `EXISTS` оказалась эквивалентна `INTERSECT`.
